# kobibri

Сервер, который читает несколько Calibre-библиотек с ФС и отдаёт их читалкам Kobo,
эмулируя store sync API. Ключевой принцип: **синк — это реконсиляция неизменяемых
снапшотов, а не дельты по времени.**

## Документы — источник правды

| Файл | Что там | Когда читать |
|---|---|---|
| `docs/PLAN.md` | Полный план: схема БД, движок синка, маршруты, этапы M1–M10, §9 «мины» | Перед любой задачей — найти нужный раздел |
| `docs/kobo-protocol.md` | Реверс-инжиниринг протокола Kobo: точные формы JSON, заголовки, баги прошивки | Перед любым кодом, который трогает провод (`internal/kobo/**`) |
| `docs/PROGRESS.md` | Статус этапов, закрытые и открытые риски, бэклог | В начале работы и в конце |

Читай их, а не восстанавливай по памяти. В `PLAN.md` §9 и в `kobo-protocol.md` разделы
**LANDMINE** — это места, где ошибка не падает, а тихо ломает устройство.

## Перед работой

1. Открыть `docs/PROGRESS.md` — понять, какой этап текущий и какие риски открыты.
2. Открыть нужный раздел `docs/PLAN.md`. Номера разделов: §2 схема БД, §3 identity/merge,
   §4 чтение Calibre, §5 движок синка, §6 HTTP, §7 kepub и обложки, §8 UI, §9 мины,
   §10 этапы, §11 проверка.
3. Если задача касается запросов/ответов Kobo — сверить формы с `docs/kobo-protocol.md`.
   Название поля, регистр плейсхолдера и наличие заголовка здесь значимы буквально.

## После изменений — обязательно обновить доки

Это не опционально: контекст между сессиями не переживает, доки переживают.

- **Закончил этап** → в `docs/PROGRESS.md` поменять статус (`⬜` → `✅`), одной строкой
  записать, что реально сделано и чем проверено.
- **Отступил от плана** → поправить соответствующий раздел `docs/PLAN.md` и записать
  причину. План — живой документ, а не история; расхождение плана и кода хуже отсутствия
  плана.
- **Узнал новое про протокол** (поведение устройства, форма ответа, баг прошивки) →
  дописать в `docs/kobo-protocol.md` в нужный раздел, пометить `LANDMINE`, если ломается
  молча, и добавить ссылку на источник.
- **Закрыл риск** (проверил на практике то, что в плане было под вопросом) → перенести
  из «Открытые риски» в «Решённые риски» в `docs/PROGRESS.md` с фактическим результатом
  замера/проверки.
- **Появилась идея не в текущем этапе** → в «Бэклог» в `docs/PROGRESS.md`, не в код.
- **Изменилась структура пакетов, команды сборки или сами доки** → обновить эту SKILL.md.

## Инварианты — нарушение ломает всё

- `books.id` выдаётся один раз и **никогда** не удаляется и не перевыпускается. Это
  единственный идентификатор, который знает устройство. `DELETE FROM books` вне явного
  админского purge — запрещён.
- Ingest **никогда** не удаляет строки `source_books` — только ставит `missing = 1`.
- Пропажа книги на сервере **не** порождает удаления на устройстве. Удаление инициирует
  только устройство (`DELETE /v1/library/{uuid}`) → tombstone, **per-device**.
- Снапшот (`sync_points` + `sync_point_books`) неизменяем после создания. Это то, что
  делает прерванный синк возобновляемым без потерь.
- Любой эндпоинт под `/kobo/` при ошибке отвечает `200 {}`, а не 4xx/5xx: ошибка на
  второстепенном эндпоинте роняет весь синк.
- В middleware `r.PathValue` **пуст** — он заполняется только после матчинга в ServeMux.
  Токен достаётся из `r.URL.Path` (`pathToken`) и лежит в контексте. Обратное однажды
  уже привело к тому, что сервер молча отклонял все запросы.
- Все абсолютные URL для устройства строятся только через `httpx.URLBuilder`. Одно место,
  где можно ошибиться, — и ошибка в `/v1/initialization` необратима.
- `metadata_rev` растёт **только** при изменении `serving_hash` — иначе каждый скан
  устраивает шторм обновлений на всех устройствах.
- Любое изменение набора живых строк источника (вкл/выкл, приоритет, удаление) обязано
  сопровождаться пере-резолвом затронутых книг: скан их не спасёт, потому что в Calibre
  ничего не менялось и книга не попадёт в изменившийся набор. См.
  `ingest.Scanner.SetSourceEnabled`.

## Команды

```
go build ./... && go vet ./... && go test ./...
go test ./internal/store/ -run TestMigrate -v
go run ./cmd/kobibri migrate        # создать/обновить БД и выйти
go run ./cmd/kobibri serve          # KOBIBRI_DATA_DIR, KOBIBRI_LISTEN, KOBIBRI_BASE_URL
```

Схема — `internal/store/migrations/`. Менять применённую миграцию нельзя, только
добавлять следующую: `<N>_<name>.sql`, нумерация плотная с 1.

## Стиль

- Stdlib-first. Новая зависимость должна себя оправдать — список утверждённых в
  `docs/PLAN.md` §1.
- Комментарии — на английском, по делу: объясняют *почему*, особенно там, где код
  выглядит странно из-за бага прошивки Kobo. Такие места помечать ссылкой на раздел
  `docs/kobo-protocol.md`.
- Тесты на каждую мину из §9. Golden-JSON для форм на проводе, fake-device для сценариев.
